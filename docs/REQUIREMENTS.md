## R1 · 主题必须可换(商业交付,最终配色由客户敲定)
- **需求**:网站主题/配色不能写死(现在是钴蓝),要能切换;交付时最终品牌色由客户定。
- **落地方向**(对齐 MT V0.3「accent 插槽制」):
  - 主题令牌集中一处:CSS 变量 `--accent` 一族(4 值)+ 少量 surface;换主题只改这一族。
  - 提供「主题配置」能力:预置几套(浅色/深色 × 不同 accent)给客户挑,或做一个后台可配的主题设置页(存 DB/配置),支持运行时切换。
  - 守住 V0.3 红线:全画面只留**一个**高饱和 accent;状态色(danger 等)不与 accent 撞色。
- **待与客户确认**:是「客户自助选色」还是「我们按客户品牌出 2–3 套定稿」。

## R2 · 模块非独立 —— 预留「关键字段」把模块串联 + 用户可自定义
- **我的理解(明天请你确认)**:你说的"关键字节"≈**关键字段 / 关联主键**。即各模块不各存各的,要有一根**共享主键/主数据**把模块串起来,并且**用户能自定义这些关键字段**,让模块联动。
- **落地方向**:
  - 已有基础:共享核心域 `Project` / `Client` 就是这根脊柱(预算已挂 Project)。
  - 强化关联:定一个**跨模块通用关联键**(如 `projectCode` / `projectId`),项目管理、预算、设计管理都按同一主键串联——一处建项目,处处引用。
  - 用户自定义字段:提供「自定义字段/扩展属性」能力(EAV 表 或 JSON 扩展列),让用户在核心对象上增删字段,各模块共享这套扩展字段,做到"预留功能、用户自定义关键字段"。
  - 便携性:SQLite 下扩展字段用 JSON 文本列存(不用 `String[]`),迁 PostgreSQL 时改 JSONB。
- **待确认(关键)**:
  1. "关键字段"到底指:① 跨模块的关联主键?② 用户自定义的业务字段(如 楼盘/工长/保修期)?③ 还是看板里用于筛选/分组的关键维度?
  2. 自定义字段作用在哪些对象上(Project / Client / Quote?),是否需要字段级校验或权限。
