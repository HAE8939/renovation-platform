# 部署路线：极空间 NAS 内测 → 阿里云正式环境

## NAS 内测

- 运行形态：单个 Web 容器 + 反向代理，先保持 SQLite，验证真实员工使用流程。
- 数据卷：单独挂载 SQLite 数据库、`public/uploads` 上传目录和运行期 `logs` 目录；三者都纳入 NAS 快照/备份。
- 备份：每日数据库备份，上传目录按日期增量备份；恢复演练至少验证“数据库 + 上传文件”同时恢复。
- 访问：仅通过局域网或 NAS 反向代理暴露，先不开放公网；账号登录在 P4 前仍是占位模式，正式内测前需补最小访问保护。
- 凭据：SSH 说明文件只用于人工部署参考，密码和授权信息不进仓库、日志、镜像或任务卡。

## 阿里云正式环境

- 计算：阿里云轻量服务器运行 app + Caddy，HTTPS 终止在 Caddy。
- 文件：验收证据、Logo、设计交付物统一抽象为文件存储服务；正式环境切 OSS，数据库只保存对象键和元数据。
- 数据库：用户数和并发达到迁移条件时从 SQLite 迁 PostgreSQL；迁移前先完成备份、回滚和读写切换演练。
- 迁移顺序：先统一文件抽象 → NAS 内测验证 → OSS 适配 → 登录/权限 → PostgreSQL。
- 监控：保留 stdout 错误采集与 `logs/app-errors.jsonl`，部署时接服务器日志轮转；不把运行日志提交进 Git。
