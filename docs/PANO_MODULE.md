# 全景管理模块 · 使用与运维（M15-a）

> 面向：往平台里放导览的人，以及在 NAS 上排障的人。
> 契约口径见 `AGENTS.md` §4.7；本文只讲怎么操作、怎么查问题、和哪里与 MT-Pano 耦合。

## 1. 这个模块做什么、不做什么

做：把**本地全景编辑器已经导出的**静态导览目录收进来，按项目归集成一个可搜索的归纳页，并提供能直接点开环视的浏览页。

不做：**不做全景编辑**（切片、热点、平面图打点、品牌主题都在 `E:\19 Python File\MT-Pano\editor` 里做）；**不对外发布**（内测期只内网可达，见 §6）。

一个导览 = 一个目录，形如：

```text
<某个目录名>/
  index.html        ← 入口，必须有
  app.js            ← 导览数据与逻辑（场景、热点、初始视角）
  style.css
  brand.css         ← 品牌主题（build_tour.py 注入）
  marzipano.js      ← 运行时（拿不到本地副本时导出物会改引用 CDN）
  plan.png          ← 平面图（编辑器里挂了的话）
  logo.svg          ← 品牌标识
  project.json      ← 只有完整版有；托管版会删掉
  tiles/<场景 id>/  ← 立方图瓦片 + preview.jpg（+ 完整版才有 source.jpg 原图）
```

**导览包内部全部是相对路径引用**（实测 MT-Pano 的导出生成器），所以整包挂在
`public/uploads/pano/` 下就能直接 iframe 打开，平台不需要改写它的任何文件。

## 2. 发布一条导览（完整流程）

1. **本地导出**：在 MT-Pano 仓库 `editor/` 下按 README 构建，产物在
   `editor/panotour/dist/<品牌>_<项目名>_web/`（同目录还有可发布的 `_托管版_web/`）。
2. **放进服务器**：把**解压后的整个目录**放到平台的 `public/uploads/pano/` 下
   （放法见 §3）。目录名随意，但**不能含 `/` `\` : * ? " < > |`、不能以点开头、首尾不能有空格**；
   中文可以（MT-Pano 默认 slug 就是 `品牌_项目名`）。
3. **登记**：平台侧栏「全景管理 → 登记管理」→ 点右上「重新扫描」→ 在「待登记」里选目录 →
   挂到对应项目 → 「登记导览」。标题留空会自动取导览包里写的标题。
4. **看效果**：「项目归纳」出现卡片；项目详情页的「全景导览」页签里也有它。

同一项目可以并存多条导览（毛坯版 / 竣工版 / 阶段记录），用列表里的「上移 / 下移」决定展示次序。

## 3. 文件怎么放到服务器上（三条路，按场景选）

全景成品不是通过浏览器上传的——一个导览动辄几百个文件、几十上百 MB，走浏览器既慢又要把
20MB 的单文件上限改开。定的路子是**放目录 + 扫描登记**。三种放法：

- **NAS（极空间 Z0220021）当前形态**：导览落在容器里的 `/app/public/uploads/pano/`，
  它属于 named volume `renovation_uploads`。宿主机上的实际位置用
  `sudo docker volume inspect renovation_uploads -f '{{ .Mountpoint }}'` 查，
  然后把目录放进其下的 `pano/`（记得 `sudo`，当前用户不在 docker 组）。
- **换更大/更方便的盘**：如果要把导览放到某个媒体卷而不是 docker 卷，把部署脚本里的
  `-v renovation_uploads:/app/public/uploads` 改成对该目录的 bind mount 即可；
  **`compose.internal.yml` 与 `deploy/nas-deploy.sh` 两条路等价，改一个必须同步另一个**（§7.2）。
- **本机开发**：直接往仓库的 `public/uploads/pano/` 里放（该目录整体被 gitignore，不会误提交）。

放完不会自动生效——平台感知不到文件系统变化，要在登记管理页点「重新扫描」。

## 4. 磁盘余量：先看这条再放文件

NAS 上 docker 数据根在 `/data_s002`，实测**已用 96%**；系统盘只剩约 9G（见 `AGENTS.md` §7.2）。
一条 2:1 全景导览按场景数与瓦片层级，几十到几百 MB 很正常。所以：

- 放之前先在本地量一下：`du -sh <导览目录>`；登记管理页也会显示每条的体积与总占用。
- 优先用**托管版**导出（`_托管版_web`）发布，完整版留在本地当母版可回编辑——
  托管版删掉每景 `source.jpg`（约占一半体积）与 `project.json`。
- 空间不够时先删最旧的阶段版本目录（先在平台上「解除登记」，再删目录，顺序别反）。

## 5. 排查表

| 现象 | 原因与处理 |
| --- | --- |
| 扫描出来在「磁盘上有目录，但打不开」 | 多半只放了 zip 没解压（提示语会写「缺 index.html」）。解压整个目录再扫。 |
| 「待登记」里看不到刚放的目录 | 没点「重新扫描」；或目录名不合规（含 `/`、以点开头等）；或放错了根目录（页面顶部会显示平台实际在扫的路径）。 |
| 登记时提示「找不到目录」 | 同上，路径对不上；确认放的是 `uploads/pano/` 的直接子目录，不是再嵌套一层。 |
| 卡片没有封面 | 包里找不到 `tiles/<第一幕>/preview.jpg`，也没有根级 `cover.*`。会在卡片上诚实显示「该导览未提供封面」，不是 bug。 |
| 场景数显示「未记录」 | 用的是托管版导出，包里没有 `project.json`。在「编辑」里手工填一次即可（0 不代表没有场景）。 |
| 某条在归纳页看不到 | 看登记管理里它的标记：「已下架」或「归属项目已归档」。归纳页底部也会如实报这两类各多少条。 |
| 点进去 404 / 「文件不在」报警 | 库里有登记但磁盘目录被改名或移走了（对账页的 `missingOnDisk` 一堆）。把目录放回原名再扫描。 |
| 换服务器 / 重建容器后导览全没了 | uploads 卷没挂上。检查 `-v renovation_uploads:/app/public/uploads` 是否还在。 |
| iPad / iPhone 上「全屏」按钮没反应 | iOS Safari 不允许普通元素全屏，只有 `<video>` 可以。页面会给出提示：改用「新窗口打开」+ 转横屏。 |
| 导览里图片裂开 | 只拷了部分文件（比如只拷了 `index.html`）。导览包必须整包搬运。 |

## 6. 要给客户看怎么办（本轮**未实现**）

2026-10-18 拍板：内测阶段不实现公网发布。将来走云端时，推荐形状是——
把托管版导览目录放进阿里云 OSS 桶（静态网站托管 + 只读），平台里只保存并展示那个对外链接；
**不要**把整个平台发到公网（它装着 HR 与财务，且 §7.1 的口令保护当前是 `PLATFORM_GATE=off`）。
届时要一并解决：链接防猜（token 化目录名）、封面与项目名是否可对外、以及到期撤下。
本轮刻意**没有**在 `PanoTour` 里预留 `shareUrl` 字段——留了就是提前实现未来需求。

## 7. 与 MT-Pano 的耦合点（改了那边要同步这里）

| 平台侧假设 | 出处 | 平台侧位置 |
| --- | --- | --- |
| 入口文件名是 `index.html` | MT-Pano `catalog/README.md` 收录约定 | `src/modules/pano/types.ts` 的 `PANO_ENTRY_FILE` |
| 封面取 `tiles/<场景>/preview.jpg` | `MT-Panoramic/server/index.js` 导出器 | `PANO_COVER_FILENAMES` + `pickFirstSceneDir` |
| 标题与场景顺序读 `project.json` 的 `settings.title` / `scenes[].id` | 同上（完整版才有） | `src/modules/pano/server/scan.ts` 的 `readPackMeta` |
| 包内引用是相对路径 | 同上（编辑器预览才改写成根绝对） | 整模块依赖；若那边改成根绝对，iframe 就必须在独立前缀下服务 |

`scripts/verify-pano.mjs` 里有一条断言专门钉住入口文件名（`index.html`），
它变红就是在提醒：这两边开始漂移了。
