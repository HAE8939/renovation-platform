## 5. 踩过的坑（每条都有代价，防返工）

- **`core/ui/Input.tsx` 基类硬写 `w-full`**：Tailwind 生成 width 工具类时 `full` 排在数字档之后，单实例传 `w-24` **被静默压掉**。表现是编号框撑到 410px、名称框反被挤窄。正解：外层容器定宽、Input 只填满容器。**别改 Input**，会波及全站。
- **`manifest.nav` 是全局静态清单，拿不到 `projectId`**：写 `/budget/[projectId]/xxx` 会按字面量渲染成死链（实测 404），且 `Nav` 的 `subActive` 精确匹配永不为真。**项目级入口只能放页面内部**带真实 id 的链接。
- **`Client` 是 1—N 共享主数据**：项目设置页改客户名会连带改掉该客户名下所有项目的显示，且 `createProject` 也按客户名 `upsert`。行为合理（一处改处处生效）但属意外副作用，已在表单加 `hint` 明示。
- **seed 日志按源数组常量算数**：M1a 的 `seed.ts` 只建了 `catalogCategory`、一条 `CatalogItem` 没写，日志却打印"模板 16 项"，漏项被自己的日志盖了一整天——报价明细是快照，详情页看不出模板库空，直到 M1b 建了第一个真读该表的页面才暴露。**报数一律取 DB `count` 并加自检断言。**
- **残留服务造成假绿**：`next start` 没被真杀掉时，占端口的旧进程会应答探活，于是"服务就绪 ✓"截的是旧构建（实测两次截图字节数完全一致）。`spawn("taskkill")` 异步 + 立刻 `process.exit()` 等于没杀，必须 `execFileSync` 阻塞杀进程树。
- **嵌套事务不共享连接（M3-d2 真 bug，集成门禁才抓得到）**：`signLead` 在 `prisma.$transaction` 内新建 Client，却调用 `createProject`——而后者又自开**独立** `$transaction`。SQLite 下内层事务看不见外层未提交的行 → 签约报「指定的客户不存在」。**正解：`createProject(input, tx?)` 接受外部事务客户端，`signLead` 把自己的 `tx` 传进去，全程一个事务**。教训：跨函数复用事务必须显式传 `tx`，别在事务里再调另一个开事务的服务；build/纯函数断言都拦不住，只有端到端集成能抓。
- **re-export shim 用无扩展名相对路径会坑 plain-node 门禁**：把 `budget/lib/quote.ts` 改成 `export * from "../../../core/domain/pricing"`（无扩展名）后，Next 打包器能解析（build 绿），但 `verify-quote.mjs` 用 `node` 直跑 ESM **不做无扩展名解析** → 报「找不到 pricing」。**正解**：门禁脚本直接 import 真源 `core/domain/pricing.ts`（带 `.ts`），别穿过无扩展名的 re-export 链。教训：改单一真源位置时，同步检查所有「plain-node 直跑」的门禁脚本的 import 目标。
- **免费编码通道有两种死法**：429 是 TPM 速率限制（非当日额度，冷却可续）、502 ECONNRESET 是传输层瞬断且**零写盘**。对策都是**一轮只给一个界面单元** + 失败原卡重跑。
- **新建 git worktree 后 `pnpm install` 不会自动 `prisma generate`**：直接跑 seed 报 `@prisma/client did not initialize yet`。准备序列是 `install → prisma generate → migrate deploy → db seed`。
- **linked worktree 不能放进主仓工作树内部**（git 视其为未跟踪目录，且与 `src/**` 构建 glob 冲突），必须同级；并行轨失效后及时 `git worktree remove` + 删目录，只留分支承载历史。
- **V0.3 淡边框会让 375 截图"看着像溢出"，实则未必**（M5-b 踩过：把极淡 `border-line` + 右对齐值贴边误判成整页横向溢出，差点瞎补 `min-w-0`）。判 375 是否真溢出**别只信肉眼**——用无头 Edge 同源 iframe 探针量 `documentElement.scrollWidth ≤ innerWidth`（`public/__probe.html` + `--dump-dom`，用完 `host_safe_delete`）。M5 三页实测 scrollWidth 均 ≤ 视口，横向滚动都在 `overflow-x-auto` 容器内、不破 body。这也顺带给了 §4-1 那个"成因未定位"的 budget 详情 375 溢出一个可复用的排查工具——**M8.5 已用它完成复查并关闭 §4-1**（v2 探针加「越界元素是否被 overflow 容器裁切」判定 + 徽章定点）。
- **`--headless=new` 的「缺口」截图多半是渲染裁剪，不是溢出**（2026-10-10 实测）：新版无头窗口有 ~500px 最小宽度限制，`--window-size=375` 实际是「按宽版渲染后裁到 375」，所以内容"看着被切"——真值一律以上一条的 iframe 探针为准（M6 五轮复核：甘特/模板/空态/项目 Tab 全部 scrollWidth ≤ 375）。截图只作设计目检。
- **后台跑批完成通知不可靠**（2026-10-10 实测：M6-b 那轮 codebuddy 跑完，系统完成通知未弹，靠人工发现）→ 集成者对后台任务采取**主动守候轮询**（每 45–55s 查输出日志非空即知完成），不静等通知；等待期间可并行备下一单元提示词。
- **「隔离库集成门禁」会改库、不可直接重跑**（M7 实测踩过）：`verify-quality-flow.mts` 在同一未重置的库上二次运行，会依据上次运行的残留状态报一连串误导性 FAIL（「前置」断言全红）。正解=**每次跑前先 `migrate reset --force`**（针已写进脚本头注 + 初态守卫：库非初始态即打印重置命令并退出）。
- **`print-pdf.mjs --path` 的 `/` 开头参数会被 Git Bash（MSYS）改写路径**：`/quality/archive/...` 被转成 `D:/DevTools/Git/quality/...` → `ERR_INVALID_URL`。正解=前置 `MSYS_NO_PATHCONV=1`（同 blog 仓 publish:note 的坑）。另：`next start` 对**启动后新增**的 `public/` 文件不生效（探针文件须在启动前放好，或重启服务）。
- **演示数据的时间自洽要主动回填**：节点/问题 `createdAt` 若停留在 seed 运行时刻，档案时间轴会出现「生成晚于提交」的反序（M7-d 实见）。正解=seed 演示流统一回填（节点于工序实际完工日生成、问题于退回时刻生成）；**生产 `syncAcceptanceNodes` 用真实时刻、不回填**。M8-a 按同法：付款段 `paidAt` 取节点 `reviewedAt`+1d、7 笔支出按各自开工日 +12~+55 天落在施工期内（越过今天则钳回昨天），避免已竣工项目出现「完工后才买主材」的反序。
- **纯函数算出来了、页面却没把它渲染**（M8-a 实见，靠截图抓到）：`/finance` 里 `marginText`（毛利率数值）定义了却没用，毛利卡只显「毛利率」三个字不显数值——`tsc` 不报（未开 `noUnusedLocals`）、build 绿、115 断言全过。**教训：口径类字段要在目检时逐个对"数值是否出现在页面上"，别只看版式。**
- **主脊字段的写侧别等下游催**（M2-A→M8 的时差实见）：`contractAmount` 在 M2-A 只落了列与读侧显示，`updateProject` 与项目设置表单都不含它，导致 M8 开工时非签约项目根本无法录入合同额、生成守卫无从手测。**动主脊加"财务/状态锚点"列时，同一批就把写入入口一起补上**（或至少在任务卡里挂一条"写侧待补"）。
- **编辑控件必须与服务层写侧语义一致，否则"改了静默不生效"**（M8-b 实见，代码审查抓到、非截图）：codebuddy 的编辑抽屉放了个可改的「项目」下拉（`<Select name="projectId">`），但 `updateRecord` 的 update data 根本不写 `projectId`——用户改项目保存后纹丝不动。它还用 `projects.find(p => p.name === record.projectName)?.id` 按名字反查 id 来填这个下拉，重名/归档项目即错位。**正解**：`updateRecord` 既然不写 projectId，就把编辑态的「项目」改**只读**（归属更正走删除重建），删掉反查与 `projects` 依赖链。教训与 M8-a「marginText 算了没渲染」同族——**纯函数/服务算了或收了字段，不等于界面把它接住了或写回了**；加编辑控件时逐个对"这个控件改了，服务写不写、写了 DB 变不变"，build/tsc/断言都拦不住这种"UI 与写侧脱节"。若确需可改归属，得同时补 `updateRecord` 写 projectId + 事务内新 projectId 存在性守卫 + 处理归档项目不在下拉的边界（那是扩范围，本卡不做）。
