# 任务：修 A4 打印导出的四处排版缺陷（只改打印这三个文件）

工作目录 = 本仓库根（分支 `feat/m1b-b1`）。打印视图已落地且两道门全绿，**本轮只修版式，不加功能**。

## 已实测确认的四个缺陷（PDF 实物，5 页 / A4 595×842pt 正确）

### 缺陷 1 · 长文本列被挤成窄条，行高爆炸
明细表里「材料说明」「施工要求」各只有约 100px 宽，一段文字竖着堆成 5–9 行；
而编号 / 单位 / 单价 / 数量这些短列反而占了大量宽度。列宽与内容信息量严重不匹配。
→ **重分配列宽**：短列收到刚好容得下内容（编号约 7 字符、单位 1–2 字、单价与数量各容 `1,234.56`、小计同），
剩余宽度全部让给材料说明与施工要求两列。建议用 `table-layout: fixed` + 显式列宽，别靠浏览器自动分配。

### 缺陷 2 · 每个科目组整组不跨页，页数翻倍
第 2 页只放了"前期准备"4 行就结束、下半页全空。16 行 / 4 组 = 4 页明细。
根因是 `break-inside: avoid` 作用到了**组级容器**（科目标题 + 其表格整体）。
→ 只在**单行 `tr` 级**保留 `break-inside: avoid`（一行不被切断），
组允许跨页；跨页时表头按现有 `thead { display: table-header-group }` 重复即可。
不要做成"每科一页"，那更浪费。

### 缺陷 3 · 「分科目明细」标题成孤行
该标题落在第 1 页底部，正文从第 2 页开始。
→ 给各级标题加 `break-after: avoid`（标题不与后文分离），必要时让明细表首行随标题走。

### 缺陷 4 · SOP 与材料的换行被吞
库里 `sop` 真值是 `"入户量房，复核图纸与实际尺寸的偏差\n业主、施工方、设计方三方书面交底\n变更范围现场确认并签字留档"`
——三条工序，打印后被压成一段连排文字（`\n` 塌成空格）。
→ 打印态给材料说明与施工要求两列 `white-space: pre-line`，让分步工序真正分行。
这是**内容保真问题**，不是美观问题：工序被连排读起来会漏步骤。
